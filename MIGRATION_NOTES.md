# Phase 7.7 — canonical-base migration notes

This branch transforms Czech-law-mcp from the legacy thick-MCP shape (src/, tools/, custom transport) to the canonical-base shape (manifest + standardised DB + 3-line Dockerfile FROM mcp-base).

## State

End-to-end validated locally:
- **461,231 provisions** (matches legacy fleet count exactly)
- **45,899 instruments** from full e-sbirka.cz seed corpus
- **content_fts FTS5** with 461,231 rows indexed
- **All 13 mcp-base law-category tools** advertised + functional (search_legislation latency 5-15 ms for real Czech queries)
- **Citation envelope** populated correctly via gateway-side enrichment from manifest

## Path-C deviations (pilot-only, must be removed before prod deploy)

These exist because the production-correct catalog-signing path is blocked on arch-docs PR #712 (YAML hot-fix) + mcp-base PR #8 (license-code regex loosening). When both merge and mcp-base v0.1.1 cuts:

1. **Dockerfile.canonical** currently `FROM mcp-base:test-dev` (local image) → must change to `FROM ghcr.io/ansvar-systems/mcp-base:v0.1.1-alpine` and COPY real signed `license-catalog.json.bundle` from arch-docs Release.

2. **`MCP_CATALOG_BUNDLE_DISABLED=true` env** in Dockerfile.canonical → REMOVE. The base will verify a real Sigstore bundle.

3. **`NODE_ENV=development` env** in Dockerfile.canonical → REMOVE. Production keeps `NODE_ENV=production` from the base image.

4. **`license_code: "CZECH-STATUTORY-PD"`** (all-caps) in manifest → revert to `"Czech-Statutory-PD"` (canonical arch-docs case) once mcp-base PR #8 ships the loosened regex.

5. **`license-catalog.json`** committed in this branch as a manual pilot artifact → REMOVE. Production builds fetch it from the arch-docs Release at Dockerfile build time.

## Reproduction

```bash
npm run build:db                     # data/database.db (legacy shape)
node --import tsx scripts/migrate-to-standardised.ts   # data/database.standardised.db
docker build -t czech-law-mcp:canonical-pilot-full -f Dockerfile.canonical .
docker run -d --name czech-pilot -p 7501:7501 czech-law-mcp:canonical-pilot-full
curl http://127.0.0.1:7501/health    # {"status":"ok"}
```

MCP traffic on `http://127.0.0.1:7501/mcp` via Streamable HTTP transport.
